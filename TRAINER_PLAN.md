# codemmet train — syntax trainer (design)

A `codemmet train` subcommand: an interactive trainer that teaches the
abbreviation syntax — the composition operators first, then the per-language
trigger vocabulary. It reuses the real expansion engine to _generate_ and
_grade_ exercises, so the trainer can never drift from actual behavior.

## Decisions

- **Delivery:** a CLI subcommand, `codemmet train`, that calls the core
  `Engine` directly (no LSP).
- **What it teaches:** both, staged — the composition operators
  (`>` `+` `*` `^` `()`, glued/explicit arguments) first, then the trigger
  vocabulary per language.
- **Exercise direction:** mixed — _reverse_ (given target code, produce the
  abbreviation) and _forward_ (given an abbreviation, predict the expansion).
- **Modes:** guided lessons (primary/default), random drills, spaced
  repetition, and a free sandbox.
- **Reverse grading:** output-equivalence — an answer is correct iff it
  expands (strip mode) to the target; any valid abbreviation counts.
- **Forward answering:** mixed — multiple choice for multi-line expansions,
  free-type (graded by output-equivalence) for one-liners.
- **Interface:** a full-screen TUI (ratatui + crossterm).
- **Exercise sourcing:** hybrid — hand-authored lesson progression, plus
  auto-generated randomized instances (from the packs) for drills and review.
- **Hints:** progressive — `:hint` reveals the trigger(s), then the operators;
  `:show` (or after N misses) reveals a canonical answer and moves on.
- **Progress:** persisted across sessions (lesson completion, spaced-repetition
  schedule, accuracy/streak stats), with a `--reset`.

## Architecture: split logic from the TUI

A full-screen TUI is hard to test headlessly, so the trainer is two layers,
mirroring the existing core/LSP split:

- **`trainer` core** (pure, unit-testable, no terminal I/O): exercise
  generation, grading (via `Engine`), hint derivation, spaced-repetition
  scheduling, the progress model, and a `Session` state machine that takes
  input _events_ (`Submit(String)`, `Hint`, `Show`, `Skip`, `Next`, `Quit`)
  and returns state transitions. A seeded PRNG (a small dependency-free LCG)
  and an injectable clock make it deterministic for tests.
- **TUI layer** (ratatui/crossterm, thin): renders the `Session` state and
  translates key events into the core's input events. No logic.

New crate layout: keep it in the `codemmet` bin. Add `src/train/` with
`mod.rs` (TUI + event loop), `session.rs`, `exercise.rs`, `grade.rs`,
`review.rs` (spaced repetition), and `progress.rs`.

## Reuse

- `Engine::expand(abbr, lang, ctx, TabstopMode::Strip)` — render targets and
  grade reverse answers (output-equivalence) and free-type forward answers.
- `Registry` / `SnippetSet::iter()` — the trigger vocabulary for generated
  drills, forward-MC decoys, and hint trigger names.
- `codemmet_core::abbr::{parse, OPERATOR_CHARS}` — operator lessons and
  validating/classifying learner input.
- The `golden` snapshot cases can seed curated lesson exercises.

## Exercise model and grading

```text
Exercise {
  language, level, direction: Reverse | Forward,
  abbreviation,            // the canonical abbreviation
  target: String,          // strip-mode expansion of `abbreviation`
  decoys: Vec<String>,     // forward multiple-choice, when multi-line
  concepts: Vec<Concept>,  // triggers + operators involved (hints, SR items)
}
```

- **Reverse:** present `target`; read the learner's abbreviation; render it
  with `Engine` and compare to `target`. Comparison normalizes trailing
  whitespace per line (empty tabstop spots), so equivalence is about the
  visible code, and any abbreviation producing that code passes.
- **Forward, one-liner:** free-type the code; graded by the same
  output-equivalence comparison against `target`.
- **Forward, multi-line:** multiple choice — the real `target` plus decoys
  generated by perturbing the abbreviation (a sibling trigger, a dropped/added
  operator); decoys are checked to not accidentally equal `target`.

## Levels (staged)

1. Single triggers, no args (`pr`, `ret`, `main`, `todo`).
2. Arguments — glued and explicit (`fori10`, `fn:main`, `let:x`).
3. Nesting `>` (`fn:main>pr`).
4. Siblings `+` (`if+el`).
5. Repeat `*` (`arm*3`).
6. Climb-up `^` (`fn:main>fori10>pr^ret`).
7. Grouping `()` and full composition.

Per-language **trigger-vocabulary** drills layer in from level 2 onward,
auto-generated from the active language's pack.

## Modes

- **Lessons (default):** progressive levels; each level explains a concept,
  then runs a short set of exercises; completing it unlocks the next. Live
  preview ON (you see your abbreviation building the code — scaffolding).
- **Drills:** endless randomized exercises at a chosen level/difficulty. Live
  preview OFF (testing, not scaffolding).
- **Review (spaced repetition):** only the items currently due.
- **Sandbox:** no scoring — type abbreviations, see the live expansion, with
  the trigger list a keystroke away.

## Spaced repetition

Track _items_ = individual triggers and operator-patterns. Simple Leitner
boxes (increasing review intervals in days); a miss drops an item to box 1, a
correct answer promotes it. Due items are the ones whose `next_review <= now`.
The clock is injected so scheduling is unit-testable.

## Persistence

A progress file under the data dir (`dirs::data_dir()/codemmet/trainer.json`,
serde): lesson completion per level, Leitner boxes + due dates per item, and
stats (attempts, correct, current/best streak, last-session date, per-level
accuracy). `codemmet train --reset` deletes it. Location is documented and
overridable via a flag.

## TUI

ratatui panels: **goal/prompt**, **input line**, **live preview** (reverse: the
current expansion of what you've typed, gated by mode), **progress sidebar**
(level dots, review-due count, streak, accuracy), and a **feedback/hint line**.
Key-driven: type input, `Enter` submits, and `:hint` / `:show` / `:skip` /
`:quit` (or function-key equivalents).

## CLI

```
codemmet train [--lang <id>] [--mode lessons|drills|review|sandbox]
               [--level N] [--reset]
```

Defaults: `lessons`, resuming the last language (else `rust`). Uses the same
registry the rest of the tool does, so configured custom triggers are also
trainable; curated lesson content uses builtin triggers.

## Build

Put the whole subcommand behind a default-on `train` cargo feature (like the
`tree-sitter` feature), so a minimal build can exclude ratatui/crossterm.
New deps (behind the feature): `ratatui`, `crossterm`. Both are MIT — add them
to `deny.toml`'s allowances if not already covered.

## Milestones

- **T0 — scaffold:** `train` subcommand behind the `train` feature; the
  `trainer` core types (`Exercise`, `Session`, `Progress`); seeded PRNG +
  injectable clock; ratatui/crossterm deps.
- **T1 — core logic:** reverse + forward exercise generation (auto), the
  output-equivalence grader, hint derivation. Fully unit-tested with no TUI.
- **T2 — TUI + lessons:** ratatui event loop, the panel layout, live preview,
  input handling, hints/show; the guided-lessons mode end to end.
- **T3 — the other modes:** drills, spaced repetition (Leitner + persistence),
  sandbox, stats/streaks, `--reset`.
- **T4 — content + polish:** hand-authored lesson progression, decoy tuning,
  a `docs/trainer.md` user guide linked from the docs index, and a note in
  `PLAN.md`.

## Testing

- **Core unit tests:** the grader (output-equivalence, whitespace
  normalization, multiple valid answers), exercise generation with a seeded
  PRNG (deterministic), spaced-repetition scheduling with an injected clock,
  and progress load/save round-trips.
- **Session driver test:** run the `Session` state machine through a scripted
  sequence of input events and assert the transitions — this exercises the
  whole trainer logic headlessly, bypassing the terminal.
- **TUI:** kept thin and excluded from the minimal build; verified manually
  (and optionally a single headless construct-and-tick smoke).

## Risks and open questions

- **TUI testability** — mitigated by the core/TUI split; the terminal layer
  holds no logic.
- **Live preview making reverse too easy** — gated by mode (on for lessons and
  sandbox, off for drills and review).
- **Output-equivalence whitespace** — empty tabstop spots leave trailing
  spaces; the grader trims trailing whitespace per line before comparing.
- **Decoy quality (forward MC)** — generate from sibling triggers and small
  operator perturbations; reject any decoy that renders equal to the target.
- **Determinism** — a seeded PRNG for generation and an injected clock for SR
  keep tests stable; real runs seed from the system clock.
- **Open:** should reverse grading optionally reward brevity (a "shortest
  known" bonus)? Deferred — start with pass/fail on output-equivalence.
- **Open:** include user/project custom triggers in vocabulary drills by
  default, or builtins only? Start with the full registry; revisit if it hurts
  lesson determinism.
